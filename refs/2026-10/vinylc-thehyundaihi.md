## A. 프로젝트 접근 방식 (과제 → 전략 → 디자인 원칙)

> 페이지 본문을 요약했습니다. 앱의 실제 화면 품질 판단은 캡처 기준입니다.

| 단계 | 내용 |
|---|---|
| 과제 | 두 서비스(더현대닷컴·투홈)를 통합하면서, 오프라인 '더현대 서울'의 혁신 이미지를 온라인으로 옮기기 |
| 포지셔닝 | 상품을 파는 '상점'이 아니라 취향을 제안하는 **'미디어' + '커뮤니티'** → 스스로를 **'발견형 큐레이션 몰'**로 정의 |
| 핵심 전략 3 | ① **발견형 쇼핑**: 최저가 검색 대신 라이프스타일 콘텐츠를 전면 배치, 체류 시간·경험 중심 ② **오프라인 페르소나 복제**: 엄선 브랜드 3,000여 개로 '현대가 검증한 프리미엄' 유지 ③ **초개인화**: AI 쇼핑 어시스턴트 '헤이디(HEYDI)', 취향 공간을 모으는 'Gem' 기능 |
| 옴니채널 | 오프라인 매장 웨이팅·예약·테이블오더를 앱에 연결, 주문관리시스템(OMS)으로 주문 경로 일원화 → 끊김 없는 고객 경험 |
| 정보 구조 | 3개 축: **발견(피드·전문관)** / **큐레이션(아이콘샵·브랜드관·샵메인)** / **나의 공간(ME스페이스 — 개인 소셜 공간)** |
| 화면 원칙 | 잡지 화보 같은 **비정형 에디토리얼 레이아웃** + 간결하고 통일된 **정보 중심 피드** 커머스를 함께 씀 |
| 결과 메시지 | "나도 몰랐던 내 취향을 발견" |

**우리 작업에 가져갈 생각법**
- 리뉴얼 콘셉트를 기능이 아니라 **서비스의 정체성 재정의**("상점 → 미디어")로 시작합니다. 현행 진단(작업방법 1-1)의 개선 목표를 한 문장 정의로 압축하는 예시로 좋습니다.
- 전략을 **정보 구조 3축**으로 바로 연결합니다. 전략 → 메뉴 구조 → 화면 원칙이 한 줄로 이어집니다.
- 에디토리얼(감성)과 정보 피드(효율)를 **한 화면 안에서 역할을 나눠** 함께 씁니다.

## B. 결과물(앱 UI) 분석

| 관점 | 관찰한 것 | 왜 효과적인가 / 아쉬운 점 |
|---|---|---|
| 첫 화면(앱 홈) | 상단 큰 에디토리얼 배너("새로운 스타일 클래식의 재해석") → 원형 채널 아이콘 줄(RSVP, 현대식품관, ATTAG, 뷰티관…) → 2열 상품·콘텐츠 피드 | 좋음: 첫 화면이 '판매대'보다 '잡지 표지'처럼 보여 포지셔닝과 맞음 |
| 탐색 구조 | 원형 채널 아이콘으로 전문관 진입, 상단 탭(SHOP/MAGAZINE 등) | 좋음: 인스타 스토리처럼 익숙한 원형 진입점 |
| 콘텐츠 | 상품 카드와 사용자 콘텐츠(룩북·후기, 프로필·좋아요 수)가 같은 피드에 섞임 | 좋음: 커뮤니티 성격이 피드에서 바로 드러남 |
| 시각 | 흰 바탕 + 검정 + **강조색 초록 2단계(Accent Green / LightGreen)** + 할인 빨강. 사진이 주인공, UI는 절제. 둥근 모서리 카드 | 좋음: 초록 말풍선(대화형 안내)과 초록 반짝이 아이콘으로 브랜드 포인트를 일관되게 줌 |
| 아이콘 | 굵은 선 아이콘 세트 + 큰 아이콘 1개를 키라인 그리드 위에 보여줌 | 좋음: 아이콘 제작 기준(그리드)까지 공개해 시스템의 완성도를 증명 |
| 컴포넌트 | 같은 배너를 여러 크기로 보여주는 반응형 카드 변형(가로형·세로형·썸네일) | 좋음: 모듈 하나가 여러 자리에서 쓰이는 확장성 |
| 대화형 UI | 초록 말풍선 "HiHi 현대님!", "웨이팅을 시작할까요?" | 좋음: AI 어시스턴트·웨이팅 같은 기능을 메신저 말투로 친근하게 |
| 오프라인 연결 | QR 스캔 → 매장 메뉴/주문 화면, 웨이팅 번호 카드("39번째") | 좋음: 옴니채널 전략이 화면 단위로 구현됨 |

## C. 케이스 스터디 페이지 연출 (에이전시가 작업을 보여주는 방식)

| 순서 | 구간 | 연출 |
|---|---|---|
| 1 | 제목 + 메타 | 흰 바탕에 2줄 제목, Launch·Client 메타, 공유 아이콘. 그 아래 히어로 영상(Vimeo, 배경 재생) |
| 2 | 범위 + 소개 | UX·Tech 수행 범위를 작은 회색 글씨로, 서비스 정의 단락 |
| 3 | 전략 텍스트 | 소제목 + 2~3줄 설명이 반복되는 **가운데 좁은 텍스트 칼럼**(약 940px) |
| 4 | 키네틱 타이포 영상 | 키워드 문장들("HIHI 차별화 디자인 구현", "말풍선 적극 활용", "커머스에 최적화된 UI")이 **크기·농도를 달리해 흐르는** 영상. 일부 단어만 초록으로 강조 |
| 5 | 채널 회전 영상 | 가운데 폰 목업은 고정, 양옆 원형 채널 아이콘이 회전하며 폰 화면이 해당 전문관으로 바뀜 |
| 6 | 블랙 구간 영상 | 검정 바탕에 폰 + 초록 말풍선 대화, 화면 밖으로 튀어나온 정보 카드(웨이팅·예약), QR 스캔 장면 |
| 7 | 폰 목업 컷 | 주문서·결제·주문완료 등 기능 화면을 2대씩 겹쳐 배치 |
| 8 | 떠 있는 오브젝트 | 3D 렌더 상품(가방·슬리퍼·향수)과 초록 '반짝이(Gem)' 오브젝트가 폰 주변에 떠 있음 |
| 9 | 피드 확대 컷 | 앱 피드를 화면 폭 가득 크게 키워 카드 디테일을 보여줌 |
| 10 | 디자인 시스템 | 색상 칩(Primary/Inverse/Accent Green/LightGreen/Red) → 아이콘 그리드 → 반응형 배너 변형 |
| 11 | 화면 콜라주 | 검정 바탕에 폰 화면 10여 개를 엇갈린 높이로 길게 나열 |
| 12 | 크레딧 + 다음 프로젝트 | 역할별 참여자, 앱 다운로드·링크, 다음 프로젝트 배너 |

**페이지 구성 기술**: jQuery + TweenMax(GSAP 2) + Lottie, 히어로는 Vimeo 배경 영상, 본문 영상 3개는 자체 mp4 자동재생. 전체 길이 약 26,600px(1440 기준). 글꼴 Noto Sans KR + Pretendard. 메타 라벨 약 21px/700, 범위·크레딧 약 12px 회색(#909090), 본문 색 #303030.

**흐름의 리듬**: 흰 바탕(이야기) → 영상(콘셉트) → 검정 바탕(기능 몰입) → 흰 바탕(시스템) → 검정 바탕(화면 총람) → 흰 바탕(크레딧). **바탕색을 번갈아 바꿔 구간을 끊습니다.**

## 수치로 남길 것

- 색: Primary #000 계열, Inverse #FFF, Accent Green(진한 초록), Accent LightGreen(연두), Accent Red(할인) — HEX는 이미지 속 칩이라 측정 못함
- 페이지 본문 칼럼 약 940px(1440 화면), 영상·이미지는 칼럼보다 넓게
- 앱 카드: 둥근 모서리, 2열 피드, 원형 아이콘 줄

## 가져갈 패턴

- **포지셔닝 한 문장 → 정보 구조 3축 → 화면 원칙** — 콘셉트 기획서·시안 보고서 구조로 그대로 응용 가능 (기획 패턴)
- **키네틱 키워드 타이포** — 디자인 원칙 키워드를 크기·농도·강조색을 달리해 흐르게. 콘셉트 소개 구간, 컨셉서 표지에 (새 패턴 후보)
- **고정 목업 + 주변 회전 진입점** — 가운데 화면은 고정하고 주변 요소가 돌며 내용이 바뀜. 전문관·카테고리가 많은 서비스 소개에 (새 패턴 후보)
- **바탕색 교차로 구간 끊기(흰↔검정)** — 긴 스크롤 페이지의 리듬 (새 패턴 후보)
- **화면 밖으로 튀어나온 정보 카드** — 목업 옆에 핵심 UI 조각을 떼어 확대 (새 패턴 후보)
- **디자인 시스템 노출(색 칩·아이콘 그리드·반응형 변형)** — 시안 보고서·컨셉서 마지막에 넣으면 완성도 증명

## 피할 것

- 본문 영상이 자동 재생만 되고 정지 수단이 보이지 않음(접근성)
- 이미지 안에 글자·색 정보를 넣어 검색·측정이 안 됨(색 HEX를 이미지로만 제공)
- 페이지가 매우 길고(26,000px+) 중간 목차가 없음 — 시안 보고서를 이렇게 길게 만들 땐 목차나 진행 표시가 필요
